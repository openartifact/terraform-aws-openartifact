# secrets

AWS Secrets Manager secrets for the OpenArtifact application: the encryption key (`OPENARTIFACT_SECRET_KEY`), the HMAC key (`AUTH_HMAC_KEY`), an optional metrics token (`METRICS_AUTH_TOKEN`), an optional bootstrap admin password (`OPENARTIFACT_BOOTSTRAP_ADMIN_PASSWORD`) and an optional bootstrap admin API token.

Values are generated by an `ephemeral "random_password"` resource and written through the write-only `secret_string_wo` argument of `aws_secretsmanager_secret_version`, so **no secret value is ever stored in the Terraform/OpenTofu plan or state**. Requires Terraform or OpenTofu 1.11+ and AWS provider 6.x. Each secret can instead be supplied by ARN (`existing_secret_arns`), in which case nothing is created or generated for it.

## Usage

```hcl
module "secrets" {
  source  = "openartifact/openartifact/aws//modules/secrets"
  version = "~> 0.1"

  name = "openartifact"
}

# ECS: inject as container secrets (env var name => secret ARN).
# module.secrets.secret_arns_by_env
# IAM: allow secretsmanager:GetSecretValue on module.secrets.secret_arns.
```

Bring your own secret for one value and let the module generate the rest:

```hcl
module "secrets" {
  source  = "openartifact/openartifact/aws//modules/secrets"
  version = "~> 0.1"

  name = "openartifact"

  existing_secret_arns = {
    secret_key = "arn:aws:secretsmanager:eu-west-1:123456789012:secret:my-oa-secret-key-AbCdEf"
  }
}
```

Until a release is published, use the Git source instead:
`git::https://github.com/openartifact/terraform-aws-openartifact.git//modules/secrets?ref=vX.Y.Z`.

## Generated values

| Secret | Environment variable | Generated value |
| --- | --- | --- |
| `<name>/secret-key` | `OPENARTIFACT_SECRET_KEY` | 64 alphanumeric characters (the server requires at least 16 bytes) |
| `<name>/hmac-key` | `AUTH_HMAC_KEY` | 64 alphanumeric characters |
| `<name>/metrics-token` | `METRICS_AUTH_TOKEN` | 64 alphanumeric characters |
| `<name>/bootstrap-admin-password` | `OPENARTIFACT_BOOTSTRAP_ADMIN_PASSWORD` | 64 alphanumeric characters |
| `<name>/bootstrap-admin-token` | none (read from a file by the server) | `oa_pat_` + 64 alphanumeric characters |

Secrets store the bare string, not JSON, so ECS can reference the ARN directly as a container secret.

## `OPENARTIFACT_SECRET_KEY` must never be lost or rotated casually

OpenArtifact seals the private keys and credentials it stores in its database (GPG, APK, Nix and attestation signing keys, the SAML key, stored upstream credentials) with AES-256-GCM under `OPENARTIFACT_SECRET_KEY`. **If the key changes or is lost, everything sealed with it is permanently unreadable** and has to be re-created and re-distributed (for example, every client that trusts a signing key must be updated).

This module therefore treats that one secret specially:

- `secret_version` rotates the HMAC key, metrics token and bootstrap admin password/token, but **never** the encryption key (its `secret_string_wo_version` is pinned).
- The value is not stored in state, so it can only be recovered from Secrets Manager. Keep `recovery_window_in_days` at its default of 30 so an accidental delete can still be undone, and consider replicating the secret or exporting it to your own vault.
- Destroying the module, or replacing the secret or its version resource (including `-replace`, state surgery or renaming `name`), generates a **new** key and orphans the old data. Review plans that touch `aws_secretsmanager_secret.generated["secret_key"]` or `aws_secretsmanager_secret_version.generated["secret_key"]`.
- To rotate deliberately, first re-key or export what the application stored, then force a new value with `terraform apply -replace='module.<name>.aws_secretsmanager_secret_version.generated["secret_key"]'` and redeploy the workload. Alternatively manage the key yourself with `existing_secret_arns.secret_key`.

## Other security notes

- Bumping `secret_version` generates new values on the next apply; the workload must be redeployed (ECS `--force-new-deployment`, Kubernetes rollout) because the application reads secrets only at start. Rotating `hmac_key` signs every user out.
- The `bootstrap_admin_password` is only used the first time the application starts on an empty database; change it after the first login. The admin API token is read from a file only (`OPENARTIFACT_BOOTSTRAP_ADMIN_TOKEN_FILE`), so it works on Kubernetes and cannot be used on ECS Fargate.
- By default secrets use the AWS managed `aws/secretsmanager` key. Pass `kms_key_arn` for a customer managed key and grant the workload's execution role `kms:Decrypt` on it.
- Read access is controlled entirely by IAM; scope `secretsmanager:GetSecretValue` to `secret_arns`. No resource policy is attached.
- Operators who run Terraform can read the secrets through the console or CLI with sufficient IAM permissions; the write-only design only keeps the values out of the state file.
